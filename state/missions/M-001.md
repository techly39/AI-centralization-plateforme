ACCEPTANCE: `acceptance/M-001.py` is self-contained: it does not import `scripts/` and does not import `app`. It is written and committed together with the spec data it needs: `specs/metered-month/{a-analyst.yaml, b-pm.yaml, input.json}`.

- Env with every `FUND_*` variable dropped, then: `FUND_DATABASE_URL=sqlite:///<tmp>/m001.db`, `FUND_MARKETDATA__PROVIDER=synthetic`, `FUND_MARKETDATA__SYNTHETIC_KEY=sha256(b"fund-acceptance-M-001/1")`.

**The specs:**
- `a-analyst`: provider `fake-metered`, script `ma-signal-analyst-underreports`, budget_usd 20, pod 1.
- `b-pm`: provider `fake-metered`, script `signal-pm`, budget_usd 20, pod 1.
- `input.json`: `{"universe":["SYNA","SYNB"]}`.

The script runs three parts on the same App, in this order. It prints PASS/FAIL and the evidence for each part, and exits 1 if any part fails.

**Part B — the real law refuses before physics is told.**
- Read the real law in-process (`runtime.governance.read_governance()`).
  - If HALT is set: print it and exit 1.
  - If the real cap is `null`: run `uv run fund-runtime backtest --specs specs/metered-month --steps 31 --input …` as a subprocess, with the registrar and clock keys in the env.
  - If the real cap is ever numeric (the Human answered Q-0001): run the same command in-process against a temp `human.yaml` that says `null`, and print why. This keeps the check true forever.
- Assert:
  - exit code 1;
  - `ended == "refused"`;
  - `reason == "provision:wake_refused:a-analyst:cap_null"`;
  - `registered == []`;
  - no `metering` key in the outcome;
  - the event count in the ledger file (sqlite `mode=ro`) is unchanged;
  - `GET /agents` is unchanged;
  - there is no `run_minds_declared` row.

**Part C — budgets over the cap are refused before physics is told.**
- In-process: set `runtime.governance.HUMAN_YAML` to `<tmp>/law/human.yaml` with `monthly_llm_usd_cap: 30`. `HALT_FILE` is left real, so the Human's HALT still stops the check.
- Run `runtime.cli.main(["backtest", "--specs", "specs/metered-month", "--steps", "31", "--input", …])` with the keys in `os.environ`, and capture stdout.
- Assert:
  - return value 1;
  - `reason == "provision:budget_over_cap"`;
  - the ledger is unchanged.

**Part A — the metered month.**
- Same in-process call with the injected cap at 50. Assert return value 0 and `ended == "completed"`.
- **The run:** 31 steps; 62 wakes, all with `ended == "done"`. The ledger declares `{"minds":["scripted"]}`, before any firm event. The PM placed ≥ 1 order, so the month is not empty (the world key is fixed, so this is deterministic).
- **The keys:** `outcome["metering"]["keys"]` has exactly 2 keys, one per spec. Each key's `agent_id` is the id `GET /agents` gives for that spec's name. For each key: `0 < spent_usd_micros ≤ limit_usd_micros == 20_000_000`, and `charges` == the number of exchanges that spec has in `run.steps[*].wakes[*].exchanges`. That means every model turn was charged exactly once.
- **Cap kept:** Σ limits ≤ 50_000_000 and Σ spent ≤ Σ limits.
- **Whole-ledger invariant (EC4):**
  - Fold the `cost_metered` rows straight from the file: per `key_ref`, the maximum `usd_micros_total`, and the first row's agent binds the key.
  - Then, with exact integer equality: Σ per-key maxima == provisioner Σ spent == `GET /metering/agents.total_usd_micros` == Σ of `agents[*].metered_usd_micros`.
  - Per agent, the App's `metered_usd_micros` == that agent's provisioner spend.
- **Trailing block:** there are exactly 2 `cost_metered` rows. Both are by the runtime agent, both are the last two events of the ledger, and both come after the last `clock_advanced` event. One sync only, after the last step.
- **Self-report no longer counts:**
  - analyst `self_reported_usd == 0.31` (31 × $0.01); PM `self_reported_usd == 0.0`;
  - `self_report_gap_usd == round(self − metered, 2)` for each agent, both non-zero;
  - leaderboard pod 1: `total_usd_cost == metered_usd_cost == round(Σ micros/1e6, 2)`, `self_reported_usd_cost == 0.31`, `cost_adjusted_pnl == round(pnl − total_usd_cost, 2)`;
  - `conflicts == 0` and `malformed == 0`.
- **Prints:** a per-agent table (spec, agent id, key_ref, limit, charges, provisioner $, App $, self-report $, gap $), Σ provisioner == Σ ledger == Σ App, the leaderboard row, the two trailing event ids, and the refusal reasons from B and C.

**Why it fails today:**
- Part B passes today: an unknown spending provider is already refused with `cap_null`. That is correct: it is the control.
- Part C fails: the gate answers `wake_refused:a-analyst:no_metered_key`, not `budget_over_cap`.
- Part A fails: `provision:wake_refused:a-analyst:no_metered_key`. `GET /metering/agents` is a 404, and the script `ma-signal-analyst-underreports` does not exist.

**Broken builds it catches:**
- Metrics that add self-report + meter: the pod total is off by $0.31.
- A provider that charges only the first turn: `charges` ≠ the exchange count.
- A sync between steps or a per-step sync: the trailing-block assertion fails.
- A key minted before registration, or bound to the wrong id: the agent_id cross-check fails.
- A gate that opens fake-metered under `null`: Part B fails.
- A Σ-limits check that is missing: Part C fails.

Runtime is about 31×2 wakes plus App startup, well under 15 min (measure it at M1 and print the elapsed time). It is offline, localhost only, and spends $0 real.

DESIGN: Runtime half first, then one physics read. The dependency law holds: `runtime` reaches physics only through `FundClient`, and `app` imports no runtime code.

1. **`runtime/gate.py`**
   - Add `METERED_PROVIDERS = frozenset({"fake-metered"})` and `METERED_ADAPTERS = frozenset({"native"})`.
   - Signatures: `decide_wake(provider, adapter, *, metered: object = False)` and `decide_wake_under(provider, adapter, law, *, metered: object = False) -> Decision`.
   - Order: `halted` → `zero_cost` → `cap_null` → `Decision(True, "metered")` only if `metered is True` and `type(provider) is str and provider in METERED_PROVIDERS` and `type(adapter) is str and adapter in METERED_ADAPTERS` → otherwise `no_metered_key`.
   - The gate is told by the Runtime that a key exists. It never asks the provider object.
2. **`runtime/metering.py`** (no network in any new class)
   - Copies pinned by tests: `MAX_METERED_USD_MICROS = 10**12` and `KEY_REF_PATTERN` from `app/limits.py`.
   - `usd_to_micros_floor(usd: float) -> int`, computed via `Decimal(repr(usd))`, floored.
   - Fake price: `FAKE_IN_MICROS_PER_TOKEN = 3`, `FAKE_OUT_MICROS_PER_TOKEN = 15`. `fake_charge(request, response) -> tuple[int, int, int]` gives tokens = ceil(len(sorted compact ASCII JSON)/4) for the request and for the response (reuse the serialisation of `runtime.cassette.request_sha256`), and micros = 3·in + 15·out.
   - `@dataclass(frozen=True) class Meter: provisioner: FakeProvisioner; key_ref: str`, with `charge(micros)`.
   - `FakeProvisioner.create_key` refuses a limit above `MAX_METERED_USD_MICROS` and a label that fails the pattern. Add `limit(key_ref)`, `agent_of(key_ref)` and `charges(key_ref)`, and count charges in `charge`.
   - `class FakeMeteredProvider: name = "fake-metered"; spends_money = True; __init__(self, script: Script, meter: Meter)`. `complete()` runs the script, computes `fake_charge`, and calls `meter.charge(micros)`. That raises `LimitExceeded` before anything is returned, so nothing past the limit is ever spent and the wake ends `error/provider_error:LimitExceeded`. It returns the response with `usage=Usage(in, out, micros/1e6)`.
3. **`runtime/registry.py`**
   - `PROVIDER_CLASSES["fake-metered"] = metering.FakeMeteredProvider`.
   - `check_spec`: fake-metered needs a known `script` (`unknown_script`), no `model` (`contradiction`) and `budget_usd > 0` with a micros limit > 0 (`no_budget`). `script` is allowed for `scripted` and `fake-metered`.
   - `build_provider(spec, tape=None, meter=None)`: fake-metered needs `type(meter) is Meter` and no tape, otherwise `unavailable`. A meter handed to any other provider is a `contradiction`.
4. **`runtime/scripted.py`**: `self_reporting(script, usd_per_wake: float) -> Script`.
   - When the inner script replies with no tool calls, the wrapper replies with `report_cost(tokens_in=1000, tokens_out=100, usd_cost=usd_per_wake, task_label="wake")`, call id `self-report`. When the last tool result answers `self-report`, it replies done.
   - Register `SCRIPTS["ma-signal-analyst-underreports"] = self_reporting(ma_signal_analyst, 0.01)`. Standard library only; the pinned-import tests still hold.
5. **`runtime/native.py`**: `wake(..., meter: Meter | None = None)` calls `decide_wake(spec.provider, spec.adapter, metered=meter is not None)` and then `build_provider(spec, tape, meter)`.
6. **`runtime/lockstep.py`**
   - `Mind(spec, client, meter: Meter | None = None)`. `run_backtest` passes `meter=mind.meter` to `wake`.
   - Before step 0: a metered mind's `meter.provisioner.agent_of(key_ref)` must equal its `/me` id, otherwise `refused meter_mismatch:<id>`. All meters must share one provisioner, otherwise `meter_mismatch`.
   - At the top of every step (where HALT is read): if there are meters, Σ limits must be ≤ `usd_to_micros_floor(cap)` under a fresh `read_governance()`, otherwise `refused metered_over_cap`. If the cap becomes `null`, the next wake gets `cap_null` as today. This stops a caller who hands in minds from going around `vet`.
   - `mind_kinds`: `_KIND["fake-metered"] = "scripted"`. The condition becomes provider ∈ `ZERO_COST_PROVIDERS ∪ METERED_PROVIDERS` and adapter `native`. A fake metered mind is code chosen from a closed table, and this keeps red-team 0020's "no spec vet passes is declared model".
7. **`runtime/provision.py`**
   - `vet(specs, law)`: for metered specs, ask the gate with `metered=True`; under a `null` cap that still answers `cap_null`. After the loop: each limit ≤ MAX (`budget_too_large:<id>`), and Σ limits ≤ `usd_to_micros_floor(law.monthly_llm_usd_cap)` (`budget_over_cap`).
   - `provision(specs, registrar, connect, *, provisioner: FakeProvisioner | None = None)`: if there is a metered spec and no provisioner → `ProvisionError("no_provisioner")`. After each registration and connect, `key_ref = provisioner.create_key(made["id"], limit)`; a failure is `ProvisionError(f"key_failed:{spec.id}", [*done, spec.id])`. Return `Mind(spec, client, Meter(provisioner, key_ref))`.
8. **`runtime/cli.py`**
   - `_conduct` creates `FakeProvisioner()` only if a spec is metered and passes it to `provision`.
   - After `run_backtest` returns (any end), or after a `ProvisionError` once keys exist: `await sync_costs(provisioner, clock)`. Catch the 401/403 raise as `sync.error`.
   - The outcome gains `"metering": {cap_usd_micros, keys:[{spec_id, agent_id, key_ref, limit_usd_micros, spent_usd_micros, charges}], total_usd_micros, sync:{posted, unchanged, refused, halted, error}}`, **only for metered runs**. The shape of a scripted run's outcome and cassette v1 are untouched.
   - Exit 0 only if `completed` and the sync is clean (no `refused`, no `halted`, no `error`). Otherwise exit 1, with stderr `fund-runtime: <n> metered micro-dollars not attributed: …`. This is the "fail loudly" item.
   - `_backtest` with `--cassette` and a metered spec → exit 2 ("a metered run's cassette is not defined yet").
   - `status` asks the gate with `metered=` exactly as `vet` does.
   - No new flag and no new env variable.
9. **Physics read:**
   - `app/metrics/metering.py`: `AgentMetered.keys: int`. New `metered_summary(session) -> MeteredSummary`: per metered agent, micros and the self-reported $ (one grouped `Cost` sum), plus `conflicts`, `malformed` and `total_usd_micros` (`None` when there are no metering rows). It reuses `metered_by_agent`.
   - `app/api/metering.py`: `GET /metering/agents` under `require(Action.READ_CROSS_POD)` (management and system; no new Action) → `MeteredAgentsOut{agents:[{agent_id, pod_id, metered_usd_micros, metered_usd, self_reported_usd, self_report_gap_usd}], total_usd_micros, conflicts, malformed}`. Schemas go in `app/api/schemas.py`. `key_ref` is never returned.
   - `mcp_server/tools.py`: `get_metered_costs()`.
   - No event, migration or reducer.
   - This closes audit c34 WARN 3.
10. **ADR-044** in `bible/07_DECISIONS.md`; design note `docs/metering_v1_runtime.md`; tick EC4 in `bible/05_ERAS.md` with the acceptance path.

INVARIANTS:
- The real `governance/human.yaml` cap stays `null`.
- A numeric cap exists only by rebinding `runtime.governance.HUMAN_YAML` inside a test or acceptance process. No `runtime/` module rebinds it (the existing AST test), and no CLI flag or env variable reaches it.
- The CLI never accepts an injected law.
- HALT is still read fresh before every step, wake, batch and registration. The acceptance leaves `HALT_FILE` real.
- Gate order is fixed: halted > zero_cost > cap_null > metered/no_metered_key. Exact-`str` names; `metered is True` only.
- Every metered mind holds exactly one key, bound to its own agent id. Σ limits ≤ floor(cap micros) at provisioning and at every step. A key never spends past its limit (all-or-nothing charge).
- Every model turn of a metered mind is charged exactly once.
- Sync happens once, after the run ends, whatever the end. The `cost_metered` rows form a trailing block.
- The ledger is the only store for metering. `rebuild-state` cannot disagree, and the new read is a pure fold.
- A metered agent's self-report never enters the authoritative total. Σ authoritative (pods + pod-less metered) == Σ per-key maxima.
- Permissions live only in `permissions.py` (READ_CROSS_POD reused). A 403 is logged as `permission_denied`.
- Every endpoint has an MCP tool. `null`, not 0, for unmeasured totals.
- Deterministic: same world key + specs → same charges, same ledger. No LLM call in `app/`.
- No new network client in `runtime/`. `fake-metered` is a closed-table name for a no-network class.
- `compare-ledgers` is unchanged: exactly one allowed difference.

RISKS:
- **Old tests this law breaks.** These are findings for ADR-044, not tests to loosen:
  - `test_runtime_native.py::test_every_registered_name_is_on_the_gates_list_and_says_so`: the provider table is no longer a subset of the zero-cost list, and `spends_money` is True for fake-metered. Restate it: every name is in ZERO_COST ∪ METERED, and `spends_money` ⇔ METERED.
  - `test_run_minds.py:289`: `_KIND` values ∪ {model} == MIND_KINDS still holds; check it.
  - Any test asserting the exact `check_spec` message "`script` is for provider 'scripted'".
  - `test_redteam_0020` COMBOS should gain `fake-metered` (it still holds).
- **Art. 4 perception.** A numeric cap in an acceptance process could read as routing around the cap. Mitigation: only a fake, network-free provider can be metered. The rebinding seam already exists and is pinned. No CLI or env path exists. Part B proves the real law refuses.
- **Per-run, not per-month.** The cap is enforced per conducted run. Two runs in one month could each spend up to the cap. That is harmless with a fake, but monthly accounting across runs must exist before any real key. Add it to the R-8 gate next to B-022 (ADR-044).
- **The fake's provisioner lives only in memory.** A HALT before the sync leaves dollars unposted. They are reported in the outcome, the exit code is 1, and there is no catch-up path. Accepted for the fake; a real provisioner is queryable later.
- **Charges scale with the tool list and transcript size.** Later missions that add tools raise the month's bill. Mitigation: $20 budgets with large headroom (calibrate at M1, record the measured total in ADR-044), and the acceptance asserts relations, not dollar constants.
- **The label `scripted` for fake-metered** changes ADR-032 (p). If someone ever maps the name to a real class, the label would lie. The closed table plus the no-network AST test pin it.
- **What an agent could exploit:**
  - A mind inflating its own spend only burns its own key, up to its limit.
  - A self-report can no longer move a metered agent's cost or rank (B-000n spam is still unbounded for unmetered agents: parked).
  - The per-agent cost read is management-only and never shows `key_ref`.
  - A management mind registering a new agent mid-run gets no key, so that agent cannot spend.
- **A deactivated (retired) mind** keeps its key. Its earlier spend still syncs, because physics accepts inactive agents. Test it in M2.
- **Race:** `METER_LOCK` is per process, which is enough for a single sync (B-036 class otherwise).

RED-TEAM: yes. The mission touches the wake gate (Runtime budget code), provisioning and key limits, the registry's closed table, the minds-kind label, and the metering physics (new read). Attack surface:
- The gate: the `metered` flag type and str subclasses.

- The cap read three times (conduct, provision, step), with a cap changed between reads.

ADR: ADR-044 "Metering v1, the Runtime half" (amends ADR-032 (4)(p) and ADR-041 §7–8). Answers:
1. **How can a numeric cap exist while the Human's is `null`?** Only by rebinding `runtime.governance.HUMAN_YAML` in a test or acceptance process (the existing seam), never through the CLI, the env or config. The acceptance keeps `HALT_FILE` real.
2. **Which name is metered?** `fake-metered` only (FakeMeteredProvider + FakeProvisioner, no network). A real provider is a new name by its own ADR, with Q-0001.
3. **What does physics hear about these minds?** `scripted`: code from a closed table.
4. **How are limits set?** limit = floor(budget_usd·1e6) micros, > 0 and ≤ 10^12. Σ ≤ floor(cap·1e6) at provisioning and at every step. Per run; monthly accounting is required before any real key.
5. **When does sync happen?** Once, after the run ends, whatever the end. A refused, halted or errored sync gives exit 1 with the unattributed micros named.
6. **What about compare-ledgers?** Unchanged; a metered run's `--cassette` is refused. Sketch for the mission that replays a metered run: a recorded ledger may equal its replay plus a trailing block of k ≥ 1 well-formed `cost_metered` rows by the runtime actor, nothing after them, and none in the replay. It is reported as a second, named verdict (`IDENTICAL + METERED TAIL k rows, $x`), never folded into `equal`.
7. **Who may read per-agent cost?** `GET /metering/agents` under READ_CROSS_POD; `null` total when nothing is metered.
8. **The fake price:** $3/$15 per Mtok on chars/4.

Open questions answered by the prime rule:
- **Should the injection be a `law=` parameter instead of the file seam?** No. The file seam is smaller and already used, and it keeps one law reader with live HALT.
- **Should a `LimitExceeded` end the run?** No. It ends the wake as `error`, which is data, and the cap is still kept.
- **Should the O(n²) scan be fixed now?** No. It does not matter at one sync per run (BACKLOG).
- **Should the PM self-report too?** No. One under-reporter plus one silent mind gives two different non-zero gaps, which catches the "sum both" bug.
