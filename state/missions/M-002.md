VERDICT: ready, after three scope corrections. Make them in `state/missions.json` in the same commit that saves this plan.

1. **The recording needs its own world.** "One file is enough" cannot hold for a run recorded on an App the operator built by hand. Three facts force this:
   - The Runtime is ledger-blind (ADR-022/033/040), so it cannot read that ledger.
   - Pods are created with **no event**, and the `system` agent is created silently. So the ledger alone is not a genesis.
   - The world key is a secret (red-team 0010).

   So `fund-runtime backtest` gains `--world FILE`, a world recipe (start, admin name, pods). With it, the Runtime builds a fresh world with physics' own operator commands, conducts the run, exports the ledger with a physics operator command, and writes everything into the cassette. `replay --verify` rebuilds the same world from the recipe in the file.

   A cassette recorded with `--server` (an operator-hosted App) carries no world and no ledger. `--verify` refuses it by name.
2. **New demo:**
   `FUND_MARKETDATA__SYNTHETIC_KEY=<hex> uv run fund-runtime backtest --world specs/desk-month/world.json --specs specs/desk-month --input specs/desk-month/input.json --steps 31 --cassette $TMPDIR/m.cassette.json`, then, from any directory with the same key, `uv run --project <repo> fund-runtime replay --cassette $TMPDIR/m.cassette.json --verify`. The output is `IDENTICAL: <n> events, 0 differences, $0`. A tampered cassette gives `DIVERGED at step <s>, wake <id>, …`. Or simply run `uv run python acceptance/M-002.py`.
3. **Estimate 2 → 3; `physics: true`.** The mission touches `app/cli.py` and `app/ledger/compare.py`. Both changes are read-only operator tooling, with no law, event, endpoint or permission change. The red-team still applies (see RED-TEAM).

**Part C — a tampered reply.**

**Part E — a setup error never reads as DIVERGED.** "Never DIVERGED" means: not in stdout or stderr.
- E1: the original cassette with a wrong key (`sha256(b"other-world")`) → exit 3, line 1 starts with `"SETUP ERROR"` and names `event 1 (run_started)`.

**Part F — v1 is refused by name, and a cassette without a world is refused by name.**
- F1: write `{"cassette_version":1,"hash_format":"sha256/json-sorted-compact-ascii/1","outcome":<outcome>,"redactions":0}` canonically → `--verify` exits 2, and stderr contains `cassette version 1`.
- F2: the v2 document with `world` and `ledger` set to null → exit 2, and stderr contains `no world`.

**Prints:** each part as `[PASS]`/`[FAIL]` with its evidence (n, s, event id, exit codes, verdict lines), the elapsed time (assert < 15 min), then `ACCEPTED`. Exit 1 if any part fails.

**Why it fails today:** `fund-runtime backtest` rejects `--world` (argparse exit 2), so Part A fails. `--verify` does not exist either, cassettes are v1, and nothing exports a ledger.

**Broken builds it catches:**
- A verify that trusts `ended == completed` without comparing ledgers: D reads IDENTICAL.
- A verify that maps every non-completed end to DIVERGED, or that skips the genesis check (a wrong world then diverges at turn 0 as `world`): E1 and E3 fail.
- Specs read from `specs/` or parameters from defaults: B fails (empty cwd), and C/E3 go undetected.
- A hosted world that honours the inherited `FUND_DATABASE_URL`: the sentinel appears.
- A reader that still accepts v1, or a writer that leaks the world key: F1 and A fail.

DESIGN: Runtime first, physics only as read-only operator commands. Dependency law: the Runtime imports no `app` module. Its one new edge is spawning `<venv>/bin/fund-env` from `runtime/world.py` only.

1. **`runtime/cassette.py`** (stays stdlib only)
   - `CASSETTE_VERSION = 2`. `HASH_FORMAT` is unchanged: request hashing does not change, and the golden vector holds.
   - `MAX_CASSETTE_BYTES = 64 * 2**20`.
   - Canonical form v2: `json.dumps(doc, sort_keys=True, separators=(",",":"), ensure_ascii=True, allow_nan=False)` of the whole document. This replaces `_assemble`; v1's assembly was already sorted compact.
   - `dumps(outcome=…, parameters=…, specs=…, world=…, ledger=…) -> (text, redactions)`: serialise everything except `redactions`, `redact_count`, re-parse with `_unique_pairs` (redaction collisions are refused at write time), insert the count, re-dump.
   - `write(path, **parts)` refuses `len(text) > MAX` before creating the file.
   - `read(path) -> Cassette`, a frozen dataclass of the six parts:
     - `fstat` size > MAX → refuse before reading; also read `MAX+1` bytes and refuse if more come.
     - Check `cassette_version` first: `1` → `CassetteError("cassette version 1 is not read since M-002 (ADR-045): it carries no run parameters, specs, world or ledger, so it proves nothing; re-record the run")`.
     - Then the exact key set and the types: parameters within the `_shared` ranges; `workflow_input` an object; specs a list of `{sha256, spec}`; world null or `{"recipe": object}`; ledger null or `{"ledger_format": "fund-ledger-rows/1", "rows": list}`. Then canonical equality.
   - New helpers: `spec_sha256(body)` and `tools_sha256(tools)`, both using `request_sha256`'s serialiser.
2. **`runtime/native.py`**
   - `WakeRecord` gains `model: str | None = None` (the model asked: `spec.model`) and `tools_sha256: str | None = None`, set right after the tool list is narrowed (line ~151). `None` only for a wake refused before tools were listed.
3. **`runtime/replay.py`**
   - `Tape` gains `model` and `tools_sha256`, with exact types checked. `_tape` requires both keys.
   - `Recording.load` uses `cassette.read(path).outcome`.
   - **c32 NOTE 5:** in `divergence`, when the redacted prefix is equal: `surface` if `(record.tools_sha256, record.model) != (tape.tools_sha256, tape.model)`; otherwise `key` if `_REDACTED` is in the prefix; otherwise `surface`.
4. **`runtime/lockstep.py`**: `RunRecord.agents: tuple[tuple[str, int], ...] = ()`, the (spec_id, agent id) pairs from the existing `/me` loop.
5. **`runtime/spec.py`**: `specs_from_cassette(entries) -> list[AgentSpec]`. It checks ids are unique and sorted, that `sha256 == spec_sha256(spec)`, and runs `AgentSpec.model_validate`. Failures raise `SpecError`.
6. **`runtime/conduct.py`** (new): a pure move of `cli._conduct`, `_sync_metering`, `_unattributed` and `_is_halt`. `cli` keeps aliases, because 22 test references use `cli._conduct`.
7. **`runtime/world.py`** (new, the only module that spawns processes)
   - `WorldRecipe` (pydantic, `extra=forbid`, frozen):
     - `start`: ISO-8601, timezone-aware;
     - `admin`: matches `^[a-z][a-z0-9-]{0,62}$`;
     - `pods`: 1–16 `PodRecipe{name: same pattern, allocation: finite, 0 ≤ x ≤ 1e12}`.
     - `load_world(path)` caps the file at 64 KiB.
   - `fund_env() -> Path` = `Path(sys.executable).parent / "fund-env"`. No PATH lookup. If it does not exist → `WorldError`.
   - `child_env(db, key)`: `os.environ` minus every `FUND_*`, plus `FUND_DATABASE_URL=sqlite:///<db>`, `FUND_MARKETDATA__PROVIDER=synthetic` and the key.
   - `genesis(recipe, tmp, env) -> Keys(registrar, clock)`:
     - runs `init-db`, `start-backtest --start=<s>`, `seed-admin --name=<a>`, `seed-runtime`, then `create-pod --name=<n> --allocation=<x>` per pod;
     - always `--opt=value` single tokens, cwd = `tmp`;
     - keys are parsed with `fk_\S+` from stdout and never printed;
     - a non-zero exit → `WorldError("genesis:<cmd>:<rc>")`.
   - `export_ledger(db, env) -> dict` runs `fund-env export-ledger <db>` and parses it strictly.
   - `@asynccontextmanager hosted(recipe, key)`:
     - HALT → `WorldError("halted")` before any spawn;
     - `tempfile.mkdtemp()` for the world's dir;
     - genesis, then yields `World(tmp, db, keys, start_server)`;
     - `serve()` is a Popen of `fund-env serve --host 127.0.0.1 --port <free>`, then waits on `/health` with httpx `trust_env=False`, 30 s;
     - `finally`: SIGINT, wait(10), kill; then `shutil.rmtree(tmp)`.
8. **`runtime/cli.py`**
   - `backtest`:
     - `--world FILE` and `--server` are mutually exclusive (exit 2).
     - With `--world`: no `FUND_RUNTIME__*` keys are read. The world key must be in the env (exit 2 otherwise). `hosted()` → `conduct` → stop → `export_ledger` → `cassette.write(world={"recipe":…}, ledger=…)`.
     - Without `--world`: unchanged, and the cassette carries `world=null, ledger=null`.
     - `parameters` and `specs` are written in both modes. A metered spec with `--cassette` is still exit 2.
   - `replay`:
     - only `--cassette` (required), `--verify`, and `--server` (not allowed together with `--verify`);
     - `--specs`, `--input`, `--days-per-step` and `--max-tool-calls` are removed: specs and parameters come from the file;
     - `--verify` → `runtime.verify.main(path)`.
9. **`runtime/verify.py`** (new). `verify(path) -> Verdict` runs these steps in order:
   1. read the cassette (exit 2 on `CassetteError`: v1, size, form); no world or no ledger → exit 2 `"… carries no world: verify needs a run recorded with --world"`; specs and parameters (exit 2); `Recording.from_outcome` (exit 2); `parameters.steps == rec.steps`.
   2. HALT → exit 4.
   3. No world key → exit 2.
   4. `hosted()` genesis, then `export_ledger` of the fresh database. The fresh rows must equal `recorded_rows[:len(fresh)]`, compared as opaque tuples; otherwise exit 3 `SETUP ERROR: the world is not the recorded one: event <id> (<type>) differs`.
   5. serve; `conduct(as_cassette specs, keys, replay=rec, **parameters)`; stop.
   6. write `recorded.ledger.json` (0600) into the world's tmp dir, then run `fund-env compare-ledgers recorded.ledger.json replay.db` (exit 2 there → verdict exit 3).
   7. Verdict, from the pure function `verdict_of(outcome, compare, agents)`:
      - `completed` and `equal` → **IDENTICAL**, exit 0.
      - `diverged` → **DIVERGED** (exit 1) at the parsed `diverged:<id>:<step>:<seq>:<kind>`, or at `clock:<step>:calendar_*`.
      - `completed` and not equal → **DIVERGED** at `locate`: step, `wake <spec>` if the actor is a mind else `physics`, event id and type. A recorded row that contains `fk_<redacted>` gets kind `key`.
      - `halted` → exit 4.
      - `refused` or `error` → **SETUP ERROR**, exit 3, with the reason. This is the verdict-level close of c32 NOTE 4.
   8. stdout: line 1 is the verdict, then the evidence JSON: `{verdict, events, differences, allowed, replay_usd, where, replay:{ended,reason}, compare, cassette:{bytes,redactions}}`.
10. **Physics: `app/ledger/compare.py`**. `compare()`, `LedgerComparison` and the one allowed difference are untouched. Add:

    - `locate(rows, event_id) -> {step: number of clock_advanced rows before it, actor_agent_id, type, genesis: id < the declaration's id}`.

INVARIANTS:
- `compare()`'s law is unchanged: equal length, raw-text rows, exactly one allowed difference (the declaration). A rows file and a database give the same result.
- The Runtime imports no `app` module and never opens a database. Physics' operator commands read the databases, and only databases the Runtime created in its own `mkdtemp`.
- No HTTP endpoint, permission, event, MCP tool or tool-surface change. Request hashes of v2 runs equal those of today's code for the same run.
- The world key never enters a cassette, stdout or stderr. It passes by environment to the children only.
- Children inherit no `FUND_*` except the three set. They run only `<venv>/bin/fund-env` with the subcommands `init-db, start-backtest, seed-admin, seed-runtime, create-pod, serve, export-ledger, compare-ledgers`, with `--opt=value` tokens, on 127.0.0.1. The server is stopped and the dir removed on every path.
- HALT is read before any spawn, and as today at every step and wake.
- Determinism: the same recipe, key, specs and parameters give byte-equal cassettes (no minted key).
- Only `diverged` or an unequal ledger after `completed` reads DIVERGED. Every other end maps to SETUP ERROR (3), HALTED (4) or unreadable (2).
- The cassette reader is total: every input gives a `Cassette` or a `CassetteError`, never another exception and never more than `MAX_CASSETTE_BYTES` read.
- `null`, not `0`: `where` and `locate` are null when equal.

| A setup error never reads as DIVERGED | `verdict_of` parametrized, E1/E2/E3, wrong-key e2e |
| Only `world.py` spawns, only `fund-env` | planted AST counter-example |
| The world key never enters the cassette | byte scan in the hosted e2e |
| The compare law is not widened | the rows-file widening test |
| v1 is refused everywhere | operator path and verify |
| Every v2 wake carries `model`/`tools_sha256` | missing-key recording error |
| Every act- or ledger-changing tamper → DIVERGED | C, D, and the pinned final-text limit test, which states what is *not* covered |

RISKS:
- **Old tests this law breaks.** These are findings for ADR-045, restated, never loosened:
  - every test that builds or reads v1 cassettes (`test_cassette.py`, `test_cassette_replay.py`, `test_redteam_0018.py`, `test_runtime_cli_backtest.py` `--cassette` shape checks);
  - `test_replay_cli.py`'s flag uses (10);
  - any test asserting the exact key set of a wake or run record (new `model`, `tools_sha256`, `agents`);
  - smoke `desk_run`'s replay command.
- **Determinism is proven on one world.** Proof so far is the 5-day smoke sample plus the M-001 metered test. The 31-day acceptance is the first month-long proof. A config change (fees, symbols) between record and verify reads as DIVERGED or SETUP ERROR, which is correct (physics changed). ADR-045 states that IDENTICAL is relative to the verifying checkout.
- **The free-port race** before `serve` binds. Mitigation: `check_clock` must answer `runtime`/`backtest` with the genesis key before any registration. Residual: a same-user process could take the port and catch throwaway keys.
- **The cassette now holds the world's generating law** (the `run_started.world` record: drift, volatility, symbols, fingerprint; not the key), which is withheld from agents (B-049). It stays an operator file (0600, gitignored). Any future feature that hands a mind part of a cassette must strip `ledger`.
- **Redaction versus ledger rows.** Any `fk_…` text a mind writes into an event payload is redacted in the cassette, so a recorded run reads `DIVERGED … (key)`. A mind could do this on purpose to make its runs unprovable. That is scheming as data, and the verdict names it.
- **What IDENTICAL proves:** reproducibility (these tapes in this world, under this physics, give this ledger), not authorship. A consistent forger can write a valid cassette of a different run. Final reply text and usage are unhashed (pinned limit).
- **Cost:** about 10 s of genesis per verify. Suite time grows by roughly 1–2 min of e2e; one shared fixture keeps it there.
- **The alembic cwd bug** may have hidden callers. The fix is absolute and covered by a test.

RED-TEAM: yes, scoped. The rule's literal areas (registry, oms, marketdata, metering, halt/budget) are not touched. But the mission creates a measurement instrument (Art. 9) and gives the Runtime process spawning driven by an untrusted file. Attack goals:
- make `--verify` print IDENTICAL for a cassette whose ledger its tapes do not produce;
- make a setup error read DIVERGED, or the reverse;
- inject argv or env through recipe, spec or parameter fields;
- make the hosted world touch any database or path outside its `mkdtemp` (symlinked TMPDIR, `FUND_*` leakage);
- leak the world key or agent keys into the cassette, stdout or stderr;
- exhaust resources: size, depth, 16 pods × MAX_STEPS, an orphaned server;
- craft rows files that `read_rows_file` accepts and `compare` mis-judges.

ADR: **ADR-045 — "A run is a proof object: cassette v2, hosted worlds, `replay --verify`" (amends ADR-037, ADR-038, ADR-040; 03_WORLD §1).** It answers these questions:
1. **Where does the reference ledger come from if the Runtime is ledger-blind?** From physics' operator command `fund-env export-ledger`, run on a database the Runtime itself created for a hosted run (`--world`). There is no HTTP read and no permission change. Operator-hosted runs carry `world: null, ledger: null` and are refused by `--verify` by name. Prime rule: safer seal, and reuse.
2. **Why a recipe and not a genesis rebuilt from the ledger?** Pods and the `system` agent leave no events, so the ledger is not a complete genesis. The recipe is the operator's own commands, recorded as data and run identically twice. It is general: the fork instrument reuses it.
3. **Is the world key in the file?** No (red-team 0010). It comes from the env only, and a wrong key is a SETUP ERROR at `event 1 (run_started)`.
4. **v1 cassettes?** Refused by name everywhere. They hold no ledger, world or parameters, so they cannot prove anything. One reader means one attack surface. Re-record with the code of their commit.
5. **May the Runtime spawn processes?** Only `runtime/world.py`, only `<venv>/bin/fund-env`, with the listed subcommands, a scrubbed env, its own temp dir, and loopback. Pinned by an AST test.
6. **Verdicts and exit codes:**

   | Verdict | Exit |
   |---|---|
   | IDENTICAL | 0 |
   | DIVERGED | 1 |
   | unreadable / usage (v1, no world, no key, malformed, over cap) | 2 |
   | SETUP ERROR | 3 |
   | HALTED | 4 |

   Only a tape divergence or an unequal ledger after `completed` is DIVERGED.
7. **cost_metered:** unchanged and out of scope. A metered `--cassette` is still exit 2. ADR-044 §6 stays with the first mission that replays a metered run (R-8, or M-004 if it posts zero rows).
8. **Canonical v2** is the whole document as sorted, compact ASCII. The size cap is 64 MiB. Record the measured size of the 31-day desk cassette in the ADR.
9. **What IDENTICAL proves, and what it does not** (see RISKS).
10. **Found while planning:** `alembic.ini`'s relative `script_location` made `init-db` depend on cwd; fixed.
