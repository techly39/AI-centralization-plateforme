# Plan — cycle 0036 (architect, verbatim)

UNIT: Fix the run records for B-053 + B-054 together. B-053: a run whose specs could never wake must not reach physics (no `/run/minds` declaration, no agents). B-054: every way HALT can stop a run must end it `halted`, never `refused`. — B-053, B-054 — serves: Era I EC4 groundwork. It keeps records honest before R-6b edits the gate. It meets no exit criterion: EC1, EC2, EC4 and EC7 are all unchanged, confirmed.

WHY THIS, WHY NOW: R-6b will make `decide_wake_under` let a metered mind wake. The two places that call the gate before a run should be one known shape before that happens. Today `_conduct` calls `check_clock`, then `declare_minds`, then `provision`. The pure checks that would refuse (gate, wake policy, `check_spec`, reserved or duplicate names) run only inside `provision`, after the declaration. Separately, three HALT paths report `refused`. Both fixes are small and touch the same function, so they fit one cycle.

SLICE: whole. Deferred: B-023 (halt observability), and the known gap that a `name_taken` refusal still happens after the declaration. That one needs a network read and only ever leaves a zero-cost label; note it in the backlog under B-053.

DESIGN:
- `runtime/provision.py`: move the network-free checks out of `provision` into a new `vet(specs: Sequence[AgentSpec], law: Governance) -> str | None`. It covers duplicate spec id, duplicate name, reserved name, `wake_policy_never`, `wake_refused:<id>:<reason>` via `decide_wake_under(..., law)`, and `provider_refused:<id>:<reason>` via `check_spec`. It returns exactly the reason strings `provision` raises today. `provision` becomes `if (r := vet(specs, read_governance())): raise ProvisionError(r)` and keeps everything else unchanged: the directory read, `name_taken`, and the HALT re-read before each registration.
- `runtime/cli.py::_conduct`:
  1. `law = read_governance()` once at the top, before any client is used. If `law.halted`, return `halted()`.
  2. `problem = vet(specs, law)`. If set, return `refused(f"provision:{problem}")`. Keep the `provision:` prefix so output for non-halt refusals does not change.
  3. Then `check_clock`, then `declare_minds`. If `declare_minds` returns `minds_refused:423`, return `halted()`. 423 is physics' halt code and nothing else (`app/registry/halt.py`).
  4. `provision`. On `ProvisionError`, if `exc.reason == "halted"`, or it matches `wake_refused:<id>:halted`, or `register_failed:<id>:423`, return `halted(exc.registered)`.
  - Add a local `halted(registered=())`, shaped like `refused`: `{"ended":"halted","reason":"halted","registered":[...],"run":None}`.
  - Put the halt-reason test in one small private predicate, `_is_halt(reason)`, with these exact patterns and no others.
- `runtime/lockstep.py::run_backtest`, in the per-mind loop: if `record.ended == "refused" and record.reason == "halted"`, set `stop = ("halted", "halted")`. This branch must come before the `no_identity` and replay-divergence branches. The refused wake stays in the step's `wakes` as recorded, and the clock does not advance.
- Do not change `native.wake` (the WakeRecord shape and cassette tapes stay the same), and do not change `gate.py`.
- Exit codes are unchanged: `halted` already gives exit 1. `--cassette` already writes a run whose `run` is `None`.

INVARIANTS:
- One law read decides the whole pre-gate. `provision`'s own read and its per-registration HALT re-read stay.
- Under a null cap, nothing physics records (declaration, agent, `model` label) comes from a spec the gate refuses.
- HALT never wakes anything and never moves the clock (Art. 5). The label is the only thing that changes.
- A non-halt refusal keeps its current label byte for byte.
- Permissions stay in `app/registry/permissions.py` (no `app/` change at all). Determinism holds and the ledger stays rebuildable. No new endpoints, so no new MCP tools.

RISKS:
- `_is_halt` over-matching would relabel a real refusal as halted. Hence exact patterns, and the counter-example tests above.
- Two governance reads (`_conduct` and `provision`). A HALT or cap change between them is caught by `provision`'s second read. That is acceptable, but the red-team should probe it.
- Replay: a HALT mid-replay now ends `halted` instead of `refused`. That is correct by ADR-040 (2), since halt is not divergence. Check that no replay test pins `wake_refused:*:halted`; the grep found none.
- Exploit surface from inside the firm: an agent cannot write HALT, and 423 comes only from physics' halt check. If any other physics path ever returns 423, `register_failed:*:423` would mislabel. The red-team should confirm that only `app/registry/halt.py` returns 423.

RED-TEAM: yes. This is Runtime halt and gate code, and both backlog items say a red-team is required. Attack:
1. Any spec that passes `vet` but where `provision` refuses after the declaration, beyond the known `name_taken` gap, so a `model` label is declared and nothing wakes.
2. HALT at each await point in `_conduct` and `run_backtest` (before or after the declaration, mid-registration, between wakes, after the last wake). Expect `halted`, no advance, nothing woken.
3. A non-halt refusal disguised as halt (reason strings, a crafted spec id like `x:halted`). Spec ids are validated, but confirm `wake_refused:<id>:halted` is matched as suffix `:halted` on a reason built only from gate reasons.
4. Other 423 sources in `app/`.
5. A cap change between the two law reads.
